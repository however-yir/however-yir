# 如何阅读项目证据

[返回主页](../README.md) · [当前项目与来源](core-project-grouping.md) · [演示与验证入口](ai-matrix-demo-mainline.md)

这里说明主页中演示、设计文档、测试和贡献链接分别能说明什么，便于读者判断项目的实际范围。

## 演示、设计与测试

| 材料 | 能帮助确认的内容 | 阅读时关注 |
|---|---|---|
| 截图或演示 GIF | 界面、操作过程与预期交互 | 是否使用 mock、静态数据或真实服务 |
| 设计文档与来源说明 | 模块边界、技术取舍、继承和新增部分 | 区分设计目标与默认运行路径已实现的行为 |
| 测试与 CI | 对应提交在指定环境下的检查结果 | 提交版本、执行的任务、跳过项和失败项 |
| 回归数据集与报告 | 指定样本和指标上的结果 | 数据规模、评测方法、模型配置与适用范围 |
| 运行记录与集成日志 | 特定环境中实际执行的行为 | 依赖、配置、时间、版本与复现步骤 |
| 上游已合并 PR | 外部项目接受的具体改动 | 变更内容、评审与合并状态 |

## 来源与项目状态

- 有上游基础的项目同时提供继承部分与改造重点，入口见[项目来源说明](core-project-grouping.md)。
- 平台原型、教学项目和实验性组件保留各自状态。ForgePilot 的核心治理模块是否接入默认执行链路，以其[差异说明](https://github.com/however-yir/forgepilot-studio/blob/main/docs/fork-differentiation.md)为准。
- 主页的贡献列表记录已合并的外部 PR，并按文档、示例配置等实际改动描述。
- 截图、离线回归、真实模型评估和生产运行分别提供不同层面的证据；具体结论跟随对应材料的适用范围。

## 链接与内容维护

主页与配套索引使用当前仓库名称，演示、设计和验证链接指向实际存在的页面。项目更名、验证入口或能力状态改变时，同步更新相关介绍。

仓库已有[链接检查工作流](../.github/workflows/link-check.yml)，用于检查 Markdown 链接。文字中的旧名称、非链接路径和状态表述仍需要内容核对。具体实现与测试变更保留在相应项目的提交历史中。
